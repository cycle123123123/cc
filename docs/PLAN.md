# JMReader 执行计划

> 目标：把一个「能日常用」的原生 Android 客户端做出来，而不是一个能跑 Demo 的壳。
> 本计划以当前已完成的协议逆向与工程骨架为起点。

---

## 0. 目标与验收指标

### 产品目标

| 能力 | 说明 |
|---|---|
| 浏览 | 首页最新、分类、排行、搜索 |
| 阅读 | 详情、目录、纵向/横向阅读、图片还原 |
| 账号 | 登录、收藏、历史、签到 |
| 离线 | 章节下载、断点续传、本地阅读 |
| 稳定 | 线路自动切换、错误可恢复、不白屏 |

### 量化指标

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 冷启动到首页可见 | < 1.5s（4G，线路已缓存） | `adb shell am start -W` |
| 阅读首屏 | < 800ms | 手测 + 打点 |
| 已缓存页翻页 | < 100ms | 手测 |
| 连续阅读 100 页 | 不 OOM、不卡顿 | Android Studio Profiler |
| 崩溃率 | < 0.5%（自用标准） | 本地日志统计 |
| 弱网/断网 | 有明确错误页，可重试 | 飞行模式手测 |

## 2. 各阶段明细

### P0 环境与工程基线（0.5 天）

**任务**

1. 安装 JDK 17 + Android Studio（Ladybug+）+ SDK 35。
2. 打开 `D:\work\javdb\jmapp`，生成 Gradle Wrapper（`gradle wrapper --gradle-version 8.9`）。
3. 首次 `assembleDebug`，修掉所有编译错误。
4. `git init`，提交基线；加 `.gitignore`（`build/`、`.gradle/`、`local.properties`、`*.keystore`）。
5. 建 `docs/DECISIONS.md` 记录技术决策。

**验收**

- `./gradlew :app:assembleDebug` 成功。
- 装到真机，出现首页（哪怕是空列表）。

**风险**

- 当前机器没有 JDK/SDK，Kotlin 代码未经编译验证；预计有 5~15 处小错误。

---

### P1 MVP 真机跑通（1.5 天）

**任务**

1. 真机验证：首页列表、封面、详情、目录、阅读器。
2. 图片还原正确性抽查：用同一 aid/页码跑一次 `tools/jm_probe.py image`，
   与 App 截图对比。
3. 修 UI 问题：占位高度抖动、长图显示、返回栈。
4. 加基础日志开关（`BuildConfig.DEBUG`）。

**验收**

- 任选 3 本作品，从头读到尾，无崩溃、无错页（顺序正确）。
- 首页滚动 200 项不卡。

---

### P2 协议层加固 + 单测（1 天）

**任务**

1. 抽出纯 JVM 模块（`core`），让加密/解析不依赖 Android：
   - `JmCrypto.md5/token/decryptPayload`
   - `ImageDescrambler.segmentCount`
   - `AlbumSeriesParser`
2. 用真实响应做 fixture（3~5 份 JSON，脱敏后放 `src/test/resources`）。
3. 单元测试：
   - 固定 ts 的签名与解密结果
   - 分条数表（覆盖 aid < 268850 / 268850~421925 / ≥421926 三档）
   - 分条还原：构造纯色分条位图，断言像素顺序
4. 网络层：
   - 401 / 403 / 5xx / 超时 统一映射为 `JmError`
   - 线路并发探测（3 个并发，取最快），失败降级
   - 线路缓存 TTL 24h，可手动刷新
5. `VERSION`、密钥、端点全部收敛到 `JmConfig` 单一位置。

**验收**

- `./gradlew :app:testDebugUnitTest` 全绿。
- 手动把域名改成无效值，App 能在 5 秒内自动切换并恢复。

---

### P3 多话作品（1 天）

**已知缺口**：`/album` 的 `series` 字段结构未验证；`/serialization` 参数未知。

**任务**

1. 拿一本多话作品，抓 `/album` 与 `/chapter` 原始响应，确认：
   - `series` 元素字段（id/name/sort/图片数）
   - 分话是「一个 album 多个 chapter」还是「多个 album」
2. 目录 UI：按 sort 排序、当前话高亮、跳转。
3. 阅读器底部加「上一话 / 下一话」，切话时保留阅读位置选项。
4. 下一话前 3 页预取。

**验收**

- 多话作品可连续阅读 3 话，切话无需返回详情页。
- 单本作品行为不变。

**若结构复杂**：降级为「在详情页列出所有话，点击进入」，不做连续阅读。

---

### P4 搜索 / 分类 / 排行（1.5 天）

**任务**

1. 通用列表组件（网格/列表两种布局、分页、空态、错误态）。
2. 搜索页：关键词、排序、分类筛选、结果分页。
3. 分类页：`categories` / `categories/filter`。
4. 排行页：`week` / `week/filter`、`promote_list`。
5. 搜索历史（本地 Room 或 DataStore）。

**验收**

- 搜索关键词能出结果并打开详情。
- 每个页面都能下拉刷新、上拉加载更多。

---

### P5 账号体系（2 天）

**已确认**：`/login` 是 POST FormData，成功返回 `jwttoken` + 会员信息；未登录访问 `/favorite` 返回 **HTTP 401**。

**任务**

1. 登录页（用户名/密码），`/login` 成功后持久化 jwt。
2. 请求层自动附加 `Authorization: Bearer` 与 `Cookie: AVS=`。
3. 401 统一处理：清 token → 跳登录。
4. 收藏：列表、添加/取消、收藏夹（`favorite_folder`）。
5. 历史：`watch_list`（阅读时上报进度）。
6. 签到：`daily` / `daily_chk`。
7. **风控兜底**：登录失败或疑似验证码时，提供「在网页中登录」入口（WebView 拿 cookie）。

**验收**

- 登录后收藏在官方 App/网页端可见（同一账号）。
- token 过期后自动跳登录，不白屏。

**需要你提供**：一个可用的测试账号（或明确不做账号阶段）。

---

### P6 离线下载（2.5 天）

**任务**

1. 数据模型：`DownloadTask(albumId, chapterId, pages, status, progress)`。
2. `WorkManager` 队列：并发 2、失败重试、断点续传（按页记录）。
3. 存储：`files/downloads/{aid}/{cid}/{page}.webp` + 元数据 JSON。
4. 下载管理页：暂停/继续/删除/查看占用。
5. 阅读器优先读本地；本地缺失回退网络。
6. 通知栏进度。

**验收**

- 下载 1 本 39 页作品，飞行模式下可完整阅读。
- 杀进程后任务恢复。

---

### P7 阅读体验打磨（2 天）

**任务**

1. 纵向滚动 / 横向翻页切换（`HorizontalPager`）。
2. 双指缩放 + 双击放大（`transformable`）。
3. 单击切换全屏（隐藏状态栏与顶栏）。
4. 音量键翻页。
5. 预取后 3 页 + 内存 LRU（上限按可用内存动态算）。
6. 阅读进度保存与恢复。
7. 亮度调节（可选）。

**验收**

- 连续翻 100 页无 OOM、无明显掉帧。
- 退出重进能回到上次位置。

---

### P8 稳定性与发布（2 天）

**任务**

1. R8 混淆 + 保留规则验证（序列化、OkHttp）。
2. 签名配置（`keystore.properties` 不入库）。
3. 启动优化：首屏骨架、线路预热、封面渐进加载。
4. 全局错误页 / 空态 / 重试。
5. 兼容性：Android 7 / 10 / 14 各测一轮。
6. 版本号与更新检查（读 `/setting` 的 `jm3_version`，只提示不自动装）。
7. 隐私说明：不采集数据、不接第三方统计。

**验收**

- release apk 可安装、可日常使用一周无崩溃。

## 4. 风险登记

| # | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| 1 | 接口/线路变更 | 高 | 高 | 端点与密钥集中配置；保留 Python 探测脚本；WebView 兜底入口 |
| 2 | 图片源限流 / 防盗链 | 中 | 中 | 并发 ≤3、固定 Referer、失败换源、指数退避 |
| 3 | 登录风控 / 验证码 | 中 | 高 | 优先 WebView 登录拿 cookie；不做自动注册 |
| 4 | `series` 结构不明 | 中 | 中 | P3 先做 spike，最坏降级为「详情页列话」 |
| 5 | 官方升级换密钥/版本号 | 低 | 高 | `VERSION` 单点配置；升级时重跑 Python 脚本定位差异 |
| 6 | 大图 OOM | 中 | 高 | 采样解码、还原在小图上做、内存 LRU |
| 7 | 版权与分发 | 高 | — | 仅个人使用，不上架、不传播、不内置任何内容 |
| 8 | 设备兼容 | 低 | 低 | minSdk 24，避开 API 30+ 特性 |

## 6. 工程约定

1. **单一配置源**：版本号、密钥、端点全部在 `JmConfig`，不散落。
2. **错误模型**：`sealed class JmError { Network, Auth, Api(code), Decrypt, Parse }`。
3. **时间戳**：签名与解密必须同一个 `ts`，由 `signedRequest()` 一次性生成。
4. **日志**：release 不打印响应体；jwt 与 cookie 一律脱敏。
5. **提交粒度**：一个阶段一个 PR/分支，主干保持可编译。
